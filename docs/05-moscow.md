# 9. Приоритизация MoSCoW

В рамках формирования первой рабочей версии продукта (MVP) требования были распределены по методологии MoSCoW следующим образом.

| Приоритет | Требования |
|---|---|
| **Must have (Обязательно)** | US-01, US-03, US-05, US-07, US-09, US-10, US-11, US-12 |
| **Should have (Должно быть)** | US-02, US-04, US-06, US-08 |
| **Could have (Можно добавить)** | Push-уведомления, экспорт в PDF/CSV |
| **Won't have (Не будет)** | iOS, фитнес-браслеты, соцфункции, доставка продуктов |

## Must have (Обязательно)
- **US-01. Зарегистрироваться по электронной почте.** Без базового механизма создания аккаунта невозможно разделить данные пользователей и начать работу с системой.
- **US-03. Авторизоваться по электронной почте.** Необходимый механизм безопасного доступа к личному дневнику.
- **US-05. Заполнить антропометрические данные.** Без роста, веса и возраста система не сможет рассчитать индивидуальную суточную норму КБЖУ.
- **US-07. Выбрать вектор цели.** Цель напрямую определяет алгоритмы расчета нормы и направление рекомендаций.
- **US-09. Вносить дневную запись (с загрузкой фото).** Ключевая функция продукта. Автоматический анализ фотографий еды с помощью ИИ – это главная ценность системы.
- **US-10. Редактировать дневную запись (с корректировкой ИИ).** Поскольку ИИ не гарантирует 100% точность, пользователь обязан иметь возможность вручную исправить граммовку и КБЖУ.
- **US-11. Получать рекомендации от ИИ.** Ключевая особенность «умного» помощника. Без обратной связи и советов сложно достичь цели.
- **US-12. Запросить перекус.** Уникальная фича проекта, демонстрирующая интеграцию мобильного приложения с программным эмулятором (Raspberry Pi).

## Should have (Должно быть, но можно отложить)
- **US-02. Зарегистрироваться через внешний сервис.** Ускоряет онбординг, но обычная регистрация по почте полностью закрывает базовую потребность.
- **US-04. Авторизоваться через внешний сервис.** Удобно для повторных входов, но не критично для первого запуска.
- **US-06. Редактировать антропометрические данные.** Важно для долгосрочного использования (когда вес меняется), но для первой демонстрации достаточно первичного ввода.
- **US-08. Редактировать вектор цели.** Пользователь может передумать, но на старте можно обойтись однократным выбором цели.

## Could have (Можно добавить при наличии ресурсов)
- Push-уведомления с напоминаниями внести данные о питании или выпить воды.
- Экспорт дневной или месячной статистики в PDF/CSV.

## Won't have (Не будет реализовано в текущей версии)
- Поддержка платформы iOS (текущая архитектура ориентирована на Android/Java).
- Синхронизация с фитнес-браслетами и внешними трекерами активности (в MVP данные о шагах и пульсе вводятся вручную).
- Социальные функции (добавление в друзья, обмен рецептами).
- Интеграция с сервисами доставки продуктов.
