# 8. Сценарии работы

## 8.1 Сценарии работы «Посетителя»

<details>
<summary><b>Сценарий US-01. Зарегистрироваться по электронной почте</b></summary>

| Поле | Содержание |
|---|---|
| **Наименование сценария** | Зарегистрироваться по электронной почте |
| **Участники сценария** | Посетитель, Мобильное приложение, Сервер |
| **Предусловия** | Посетитель находится на экране регистрации; есть подключение к сети Интернет. |
| **Результат** | В базе данных создана учетная запись, выполнен автоматический вход в систему. |
| **Бизнес-правила** | 1. Email должен быть уникальным в системе.<br>2. Введённый пароль и его подтверждение должны полностью совпадать.<br>3. Пароль должен соответствовать требованиям безопасности. |
| **Основной сценарий** | 1. Посетитель нажимает кнопку «Регистрация».<br>2. Вводит Email, пароль и его подтверждение.<br>3. Нажимает кнопку «Зарегистрироваться».<br>4. Система валидирует данные, создает профиль и авторизует пользователя. |
| **Альтернативный сценарий A1** | Email уже используется:<br>1. Система находит введенный Email в базе данных.<br>2. Выводит сообщение об ошибке «Пользователь с таким Email уже зарегистрирован».<br>3. Посетитель вводит другой Email. |

</details>

<details>
<summary><b>Сценарий US-02. Зарегистрироваться через внешний сервис</b></summary>

| Поле | Содержание |
|---|---|
| **Наименование сценария** | Зарегистрироваться через внешний сервис |
| **Участники сценария** | Посетитель, Мобильное приложение, Внешний сервис авторизации, Сервер |
| **Предусловия** | Посетитель находится на экране регистрации; есть подключение к сети Интернет. |
| **Результат** | В базе данных создана учетная запись, выполнен автоматический вход в систему. |
| **Бизнес-правила** | 1. Внешний сервис должен вернуть подтвержденный Email.<br>2. Пользователь дает согласие на передачу данных. |
| **Основной сценарий** | 1. Посетитель нажимает кнопку «Войти через...».<br>2. Открывается окно внешнего сервиса.<br>3. Посетитель подтверждает доступ.<br>4. Система получает данные, создает профиль и авторизует пользователя. |
| **Альтернативный сценарий A1** | Отказ в доступе:<br>1. Посетитель закрывает окно авторизации внешнего сервиса.<br>2. Система возвращает его на экран регистрации без создания профиля. |

</details>

## 8.2 Сценарии работы «Пользователя»

<details>
<summary><b>Сценарий US-03. Авторизоваться по электронной почте</b></summary>

|---|---|
| **Наименование сценария** | Авторизоваться по электронной почте |
| **Участники сценария** | Пользователь, Мобильное приложение, Сервер |

| **Альтернативный сценарий A1** | Неверный пароль или Email:<br>1. Сервер не находит совпадений.<br>2. Выводится сообщение об ошибке «Неверный логин или пароль».<br>3. Доступ к системе не предоставляется. |

</details>

<details>
<summary><b>Сценарий US-09. Вносить дневную запись</b></summary>

| Поле | Содержание |
|---|---|
| **Наименование сценария** | Вносить дневную запись |
| **Участники сценария** | Пользователь, Мобильное приложение, Сервер, ИИ-агент |
| **Предусловия** | Пользователь авторизован, открыт календарь-дашборд, выбрана текущая дата. |
| **Результат** | Данные (вес, шаги, пульс, самочувствие) и фотографии приемов пищи сохранены в БД. ИИ-агент рассчитал КБЖУ блюд. Суточная статистика обновлена. |
| **Бизнес-правила** | 1. Дата не может относиться к будущему.<br>2. Вес, шаги, пульс > 0.<br>3. Поддерживаемые форматы фото: JPEG, PNG, WEBP.<br>4. В течение дня можно добавлять неограниченное количество приемов пищи. |
| **Основной сценарий** | 1. Пользователь выбирает дату и вводит вес, шаги, пульс, самочувствие, нажимает «Сохранить».<br>2. Пользователь нажимает кнопку «Добавить прием пищи» и выбирает блюдо.<br>3. Пользователь делает фото блюда или загружает его из галереи.<br>4. Система отправляет фото на сервер.<br>5. ИИ-агент анализирует фото, определяет состав, массу порции и КБЖУ.<br>6. Система отображает распознанное блюдо и сохраняет его в дневную запись, автоматически пересчитывая суточную статистику. |
| **Альтернативный сценарий A1** | Выбрана будущая дата:<br>1. Пользователь пытается сохранить запись на завтра.<br>2. Система выдает ошибку «Нельзя вносить данные за будущую дату». |
| **Альтернативный сценарий A2** | ИИ не смог распознать блюдо:<br>1. ИИ-агент выдает низкую уверенность в распознавании.<br>2. Система предлагает пользователю ввести название блюда и КБЖУ вручную. |

</details>

| **Бизнес-правила** | 1. Валидация даты и положительных чисел сохраняется.<br>2. Результат анализа ИИ не считается абсолютно точным, пользователь имеет право менять массу блюда, калорийность и БЖУ. |
| **Основной сценарий** | 1. Пользователь открывает дневную запись.<br>2. Пользователь хочет изменить количество шагов - вводит новое значение.<br>3. Пользователь замечает, что ИИ ошибся с весом порции (например, распознал 200 г вместо 150 г).<br>4. Пользователь нажимает «Редактировать» на карточке блюда.<br>5. Пользователь вручную меняет массу (граммовку) и значения КБЖУ.<br>6. Система сохраняет изменения в БД и автоматически пересчитывает итоговую суточную статистику. |
| **Альтернативный сценарий A1** | Ввод некорректных данных:<br>1. Пользователь вводит отрицательную массу блюда или текст в поле калорий.<br>2. Система блокирует сохранение, подсвечивает поле и требует ввести корректное число. |

</details>

<details>
<summary><b>Сценарий US-11. Получать рекомендации от ИИ</b></summary>

| Поле | Содержание |
|---|---|
| **Наименование сценария** | Получение персональных рекомендаций и рецептов от ИИ |
| **Участники сценария** | Пользователь, Мобильное приложение, Сервер, ИИ-агент |
| **Предусловия** | Пользователь авторизован, за текущий день внесены данные об активности и добавлен хотя бы один прием пищи (с фото или скорректированными данными). |
| **Результат** | Отображены персональные советы по питанию, физической активности и рецепты на экране. |
| **Бизнес-правила** | 1. Рекомендации строятся на основе дефицита/профицита КБЖУ и выбранной цели пользователя.<br>2. Если данных мало, система должна явно указать, что нужно сделать для получения рекомендаций. |
| **Основной сценарий** | 1. Пользователь открывает экран «Рекомендации».<br>2. Сервер собирает данные о текущем балансе КБЖУ (на основе загруженных фото и ручных корректировок).<br>3. ИИ-агент сравнивает факт с суточной нормой.<br>4. ИИ-агент формирует совет по питанию и подбирает подходящий рецепт.<br>5. Система выводит рекомендации на экран. |
| **Альтернативный сценарий A1** | Недостаточно данных:<br>1. Пользователь не загрузил ни одного фото и не внес данные о питании за день.<br>2. Система выводит заглушку: «Добавьте приемы пищи или активность, чтобы ИИ-агент смог проанализировать ваш день и дать рекомендации». |

</details>

<summary><b>Сценарий US-12. Запросить перекус</b></summary>

| **Альтернативный сценарий A2** | Нет связи с сервером:<br>1. Эмулятор не получает ответ.<br>2. Заслонка закрыта, красный свет, сообщение об ошибке сети. |

</details>
